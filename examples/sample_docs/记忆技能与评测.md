# 记忆、技能与评测

## 四种「记住」不是一回事

初学 Agent 时最容易混淆的一点：以为向量数据库就是记忆系统的全部。
实际上这是四个不同的问题，需要四套机制：

| 机制 | 回答的问题 | 生命周期 |
| --- | --- | --- |
| RAG | 从大量资料里找出**此刻**需要的信息 | 每次查询 |
| 会话记忆 | 这一轮对话之前说过什么 | 单次会话 |
| 长期记忆 | 哪些信息应该**跨任务**保留 | 跨会话，可过期 |
| 上下文工程 | 这一轮究竟把哪些信息交给模型 | 每次请求 |

判断标准很好记：
**「资料」进 RAG，「对话」进会话记忆，「结论」进长期记忆**，
而「这一轮装什么」由上下文工程决定。

## 长期记忆怎么排序

长期记忆存的是量少、稳定、结论性的信息，因此不适合也无必要做向量化。
ContextForge 用综合打分：

```
score = (0.55 × 词面相关性 + 0.30 × 重要度 + 0.15 × 时间衰减)
        × 类型权重 × 使用反馈
```

- **词面相关性**：token 集合的重叠比例
- **重要度**：写入时指定，被重复提及时会自动上调
- **时间衰减**：45 天半衰期。旧的进度类记忆自然会沉下去
- **类型权重**：偏好与目标（1.25 / 1.20）比零散事实（1.0）更值得保留
- **使用反馈**：被召回的次数带来最多 30% 的加成，且收敛很快

写入时还会做**去重合并**：与已有记忆的 Jaccard 相似度超过 0.86 时
合并而不是新增，避免「同一件事记住十遍」把检索淹没。

进度类记忆默认 30 天过期 —— 过期的任务状态比没有状态更危险。

## 技能是程序性知识

记忆是「知道什么」，技能是「知道怎么做」。

技能本身**不会自动生效**，它作为提示注入上下文，由 Agent 决定这次用不用。
这样既避免了过度自动化，也保留了可解释性。
每次使用都会记录成功率，成功率会反过来影响技能的推荐排序。

## 评测要回答哪些问题

不只看最终回答，还要能回答「为什么是这个结果」：

**检索质量**：Precision@k、Recall@k、MRR、nDCG@k、命中率。
用来判断「该找的资料找到了没有」。

**上下文质量**：压缩率、**硬约束保留率**、**关键事实保留率**。
压缩率单独看是没有意义的 —— 把上下文压到 5% 却丢掉了用户的核心约束，
那是失败而不是优化。所以必须成对地看「省了多少」和「丢了多少」。

**回答质量**：要点覆盖率、引用完整率。

**运行成本**：成功率、平均延迟、平均 token、成本估算、工具调用成功率、
平均迭代次数。

所有指标都在本地确定性计算，不依赖外部评测服务。
接上 RAGAS / LangSmith 时，只需把它们当作另一组指标源接入，
评测接口不需要改。
