# Agent Context Lab

一个基于 Python 和大语言模型 API 的轻量级 Agent 实践项目，用于学习和探索 **上下文工程（Context Engineering）** 的核心概念与工程实现。

项目围绕 Agent 的上下文管理展开，尝试解决对话历史增长、上下文预算控制、工具调用完整性校验等问题，并通过模块化设计理解 Agent 的基本运行流程。

## ✨ 项目功能

- **LLM API 调用**：通过模型 API 与大语言模型交互。
- **上下文管理**：管理对话消息，支持历史记录裁剪。
- **上下文预算控制**：在上下文长度受限时，尝试通过调整保留的近期对话来控制预算。
- **工具调用校验**：检查工具调用与工具返回结果之间的对应关系。
- **上下文压缩**：尝试提取历史对话中的关键信息，减少上下文占用。
- **异常与状态处理**：通过临时消息列表处理请求，尽量避免失败请求污染正式对话历史。

## 🛠️ 技术栈

- Python
- LLM API
- HTTP / JSON
- Python 模块化开发
- 环境变量与 `.env` 配置

## 🚀 快速开始

### 1. 克隆项目

```bash
git clone https://github.com/SSC666-sang/agent-context-lab.git
cd agent-context-lab
```

### 2. 创建虚拟环境

Windows：

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

如果 PowerShell 阻止激活脚本，也可以直接使用：

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 3. 安装依赖

```bash
python -m pip install -r requirements.txt
```

### 4. 配置环境变量

在项目根目录创建 `.env` 文件，根据 `config.py` 中实际读取的变量名填写模型 API 配置。

示例：

```env
API_KEY=your_api_key
BASE_URL=your_api_base_url
MODEL=your_model_name
```

> 注意：以上变量名仅为示例，请以项目实际代码为准。请勿提交真实 API Key 到 GitHub。

### 5. 运行项目

```bash
python main.py
```

具体运行参数及交互方式以项目当前代码为准。

## 🧠 核心设计思路

### 1. 上下文管理

上下文不只是用户当前输入，还可能包含系统提示词、对话历史、工具定义以及工具执行结果等信息。

项目通过上下文管理模块处理历史消息，探索如何在有限的上下文窗口内保留有价值的信息。

### 2. 上下文预算控制

随着对话增长，发送给模型的消息可能越来越多。

项目尝试通过调整近期对话的保留数量来控制上下文规模，并在压缩过程中检查工具调用链的完整性。

### 3. 工具调用校验

工具调用并不等于工具已经执行成功。

Agent 需要协调模型发起的工具调用、程序执行结果以及后续模型请求。工具调用与结果之间的对应关系，是保证运行流程可靠的重要环节。

### 4. 历史信息压缩

上下文压缩需要在减少消息数量的同时，尽量保留长期目标、用户偏好和任务关键事实。

简单的关键词提取可能遗漏重要信息，因此摘要策略仍有进一步改进空间。

## 📚 学习目标

通过这个项目实践以下内容：

- 理解 Agent 的基本运行流程。
- 理解 LLM API、消息列表与工具调用之间的关系。
- 掌握 Python 模块拆分与环境变量配置。
- 理解上下文裁剪、预算控制和历史压缩的基本思路。
- 初步认识工具调用链校验、异常处理与状态一致性问题。

## 🔭 后续改进方向

- 使用 Token 估算替代简单的字符数量估算。
- 改进摘要策略，减少长期目标和关键事实的丢失。
- 增加自动化测试，覆盖上下文裁剪和工具调用校验。
- 为工具调用增加更完善的异常处理、日志和执行状态记录。
- 探索持久化会话与更可靠的上下文恢复机制。

## 📌 项目定位

这是一个用于个人学习和实践的 Agent 工程入门项目，重点在于理解上下文管理与 Agent 运行机制，而不是构建完整的生产级智能体框架。

欢迎交流与改进。
