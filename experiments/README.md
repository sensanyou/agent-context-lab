# experiments · 九个可复现的小实验

这里不是「示例代码」，而是**可复现的实验**：每个脚本都先讲清楚它要回答什么问题，
再跑一遍，最后给出带数字的结论。

全部实验都满足同一条硬约束：**不需要 API Key、不需要联网、结果是确定性的**。
你可以直接跑，也可以把输出贴进文档作为证据。

```bash
python experiments/run_all.py        # 依次跑完全部 9 个
python experiments/run_all.py 03 05  # 只跑 03 和 05
python experiments/05_context_compression.py   # 单独跑一个
```

## 实验清单

| 编号 | 主题 | 回答的问题 | 关键数字 |
| --- | --- | --- | --- |
| [01](01_messages.py) | 消息、轮次与工具链完整性 | 压缩的最小单位是「消息」还是「轮次」？ | 破坏工具链后校验不通过、修复后通过 |
| [02](02_call_llm.py) | 模型适配层 | 没有 API Key 时项目还能启动吗？ | 工厂降级到离线模型且不抛异常 |
| [03](03_context_window.py) | Token 计数与分区预算 | 「上下文快满了」怎么变成数字？ | 六个分区额度；中英混排 token/字符 ≈ 0.6~1.0 |
| [04](04_prompt_injection.py) | 提示注入 | 资料里写着「忽略上面所有指令」会怎样？ | 注入进检索结果、但不进指令块、不被执行 |
| [05](05_context_compression.py) | 压缩策略对比 | 省 token 的代价是什么？ | 滑动窗口 token 降 80%、约束丢 67%；混合策略约束保留 100% |
| [06](06_hybrid_retrieval.py) | 混合检索 | 为什么要融合向量与 BM25？ | RRF 与加权融合在同一组排名上的分歧 |
| [07](07_agent_loop.py) | 图编排 | 工具返回后要做什么？ | `build_context` 执行 2 次；可中断、可恢复 |
| [08](08_memory.py) | RAG ≠ 记忆 | 四种记忆机制分别是什么？ | 同一条内容在知识库与长期记忆中的不同行为 |
| [09](09_evaluation.py) | 评测 | 怎么把「效果更好」变成一张表？ | 检索三模式 + 压缩五策略的完整对比 |

## 阅读顺序

1. **01 → 03**：先把「消息 / 轮次 / token / 预算」这四个基础概念立住。
   后面所有的取舍都建立在这些定义上。
2. **04 → 05**：进入上下文工程的核心。04 说明外部内容为什么必须当数据；
   05 用一张表量化「压缩率 vs 信息保留率」的取舍。
3. **06**：检索链路。重点是**为什么选 RRF 而不是加权融合**，而不是「用了 RAG」。
4. **07**：把前面所有能力串成一个 Agent，并说明循环为什么长这样。
5. **08**：澄清一个常见混淆 —— RAG 不等于记忆。
6. **09**：把前八步的结论汇总成一份可复核的评测报告。

## 落盘产物

- `09_evaluation.py` 会把完整报告写到 `data/report.md`（可直接作为作品集附件）。
- 其余实验只打印到终端，不产生副作用 —— 它们跑在临时目录里，用完即删。

## 约定

- 每个脚本顶部都有一段「这个实验要回答什么」，最后都有一行 `结论：`。
- 表格渲染不依赖第三方库（`_lab.kv_table` 按东亚字符宽度对齐）。
- `_lab.py` 提供统一的离线运行时构造（`offline_runtime()`），
  它同时也是「SQLite 连接必须显式关闭」这个 Windows 坑的封装。
